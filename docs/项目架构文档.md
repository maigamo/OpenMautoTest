根目录文件
README.md: 项目说明文档。包含项目简介、架构图、技术栈、如何快速安装依赖和运行测试（快速开始指南）。

Makefile: 命令行快捷方式。封装了常用的项目命令，如 make test (运行测试), make stats (统计信息), make meta-up (启动 Metabase 服务), make migrate (执行数据库迁移) 等，简化开发和CI/CD流程。

requirements.txt: Python 依赖清单。列出了项目运行所需的所有 Python 第三方库及其版本，使用 pip install -r requirements.txt 进行安装。

pyproject.toml: 项目构建与配置。用于定义项目的元数据、依赖（与requirements.txt功能类似，但更现代）以及构建工具（如 setuptools）、代码检查工具（如 ruff, black）的配置。

.env.example: 环境变量模板。提供了项目所需环境变量的示例，如数据库连接字符串、Jenkins/Metabase 的用户名密码等。实际使用时应复制为 .env 文件并填入真实配置，.env 文件本身应被 .gitignore 排除，以防敏感信息泄露。

docker-compose.meta.yml: Metabase 服务编排文件。一个独立的 Docker Compose 文件，用于快速启动 Metabase 和其依赖的 PostgreSQL 数据库服务，方便进行本地数据可视化调试。

核心目录
configs/ - 配置中心
此目录存放所有与环境、服务连接相关的配置信息。

settings.py: 全局配置。通过 python-dotenv 自动读取 .env 文件中的环境变量，并以强类型对象（如 SETTINGS.DB_HOST）的形式暴露给项目其他部分使用。也包含一些项目级的静态配置，如 SETTINGS.record_mode (记录模式：db 或 file)。

browser.py: 浏览器配置。定义 Playwright 启动浏览器的参数，如浏览器类型（Chromium, Firefox）、是否无头模式（headless）、超时时间等。

wechat.py: 小程序配置。定义小程序自动化工具（如 minium）的配置。

jenkins.yaml, db.yaml: 服务连接配置。以 YAML 格式分别定义 Jenkins 和数据库连接池的详细参数，便于阅读和修改。

scheduler.yaml: 调度器配置。定义原生调度器（APScheduler）的定时任务（cron jobs）。

common/ - 通用组件
存放项目范围内可复用的基础模块和工具。

base_page.py: 页面基类。封装了所有页面对象（Page Object）的通用方法，如元素查找、点击、输入、等待等，避免在每个页面对象中重复编写代码。

logger.py: 日志模块。配置项目日志记录器（Logger），定义日志格式、输出级别（INFO, DEBUG）和输出位置（控制台、文件）。

reporter.py: 报告模块。封装与测试报告生成相关的逻辑，如集成 Allure Report 的装饰器或辅助函数。

utils/: 工具函数。存放各种通用的辅助函数，如日期时间处理、随机数据生成、文件读写等。

orchestrator/ - 编排与调度层
项目的“大脑”，负责测试流程的触发、执行、数据记录和上下文管理。

flow_runner.py: 测试执行入口。可能是 Pytest 的一个插件或被 Pytest 直接调用的核心脚本，负责解析测试流程、调度 flows 中的测试。

recorder.py: 数据记录器。核心的数据持久化模块，负责将测试结果（成功/失败、耗时等）按照 db/models/record.py 中定义的模型写入到 PostgreSQL 数据库。

task_queue.py: 任务队列（可选）。用于实现异步测试执行或任务分发，例如使用 Celery 或 RQ。

scheduler/: 调度逻辑

builtin.py: 内置任务。定义被 APScheduler 调度的具体作业（Job），如“每日凌晨执行全量回归测试”。

trigger.py: 触发器。提供一个 REST API 端点，允许通过 HTTP 请求远程触发测试任务。

fixtures/: Pytest 夹具

web_context.py, mini_context.py: 提供测试上下文管理的 Pytest Fixtures。例如，web_context 负责初始化 Playwright 浏览器实例、创建页面对象，并在测试结束后自动关闭浏览器、处理截图等。

flows/ - 业务流程层
定义具体的、面向用户的业务场景测试。

conftest.py: 流程级别的 Fixtures。存放该目录下所有测试流程共享的 Pytest Fixtures。

login_and_buy/, cancel_order/: 具体的业务流程目录。每个目录代表一个端到端的业务场景。

test_flow.py: 测试用例文件。使用 Pytest 语法编写的测试用例，它不直接操作页面元素，而是调用 web_steps.py 和 mini_steps.py 中定义的业务步骤，实现对业务流程的验证。

web_steps.py, mini_steps.py: 业务步骤封装。将业务流程拆解成一个个高内聚的步骤函数（如 login(username, password), search_product(name), add_to_cart()）。这些函数会调用 drivers/ 目录下的页面对象来完成具体操作。这种分层使得 test_flow.py 更易读，步骤也更易复用。

drivers/ - 驱动/页面对象层
封装对系统界面的直接操作，实现 UI 细节与业务逻辑的解耦。

web/: Web 端页面对象 (Page Objects)。存放 Web 应用的页面对象类。每个类代表一个页面（如 LoginPage, HomePage），包含了该页面的元素定位符（Locators）和操作这些元素的方法（如 fill_username(), click_login_button()）。

mini/: 小程序页面对象。与 web/ 类似，但针对的是小程序的页面。

api/: API 客户端。封装对后端服务的 HTTP API 调用。自动化测试中常用于前置数据准备（如创建测试账号）或后置数据清理，比纯 UI 操作更高效、更稳定。

周边与支持目录
llm/ - 大语言模型（预留）
为项目未来集成 AI 能力预留的目录。

client.py: LLM 服务的客户端，用于连接和调用大模型 API（如 OpenAI, Gemini）。

prompt_tpl/: 提示词模板。存放用于不同任务的 Prompt 模板，如“分析失败日志”、“生成测试用例摘要”等。

services/: AI 服务

analyze_service.py: 提供基于 LLM 的智能分析服务，如失败原因根因分析。

mcp_server.py: （可能）多智能体协同平台的服务端。

scheduler_server/ - 原生调度器服务
如果不使用 Jenkins，而是用自带的调度器时，此目录将作为一个独立的服务进程运行。

main.py: 服务启动入口。初始化并启动 APScheduler 调度器。

jobs/, logs/: 分别存放该服务相关的作业定义和运行日志。

ci/ - 持续集成
存放所有与 CI/CD 流程相关的配置和脚本。

Jenkinsfile: Jenkins Pipeline 脚本。定义了在 Jenkins 中构建、测试、部署本项目的完整流水线。

docker/: Docker 相关

Dockerfile: 测试环境镜像。定义了如何构建一个包含 Python 环境、项目代码、浏览器依赖的 Docker 镜像，确保测试在任何地方都有一致的运行环境。

docker-compose.yml: 项目整体服务编排。用于一键启动整个测试项目所需的所有服务（如测试执行容器、数据库、Metabase 等）。

scripts/: CI/CD 脚本。存放被 Jenkinsfile 或 Dockerfile 调用的 shell 脚本。

db/ - 数据库
管理与数据库相关的所有内容。

migrations/: 数据库结构变更

alembic.ini: Alembic（数据库迁移工具）的配置文件。

versions/: 迁移脚本。存放由 Alembic 生成的数据库版本脚本，每次数据库模型变更（如增删字段）都会生成一个新文件，用于以可追溯、可重复的方式更新数据库结构。002_timescale_hypertable.py 表明了未来可能向时序数据库 TimescaleDB 迁移的规划。

models/: 数据模型

record.py: ORM 模型定义。使用 SQLAlchemy ORM 定义了测试结果数据在数据库中的表结构（即 test_case_runs 表），将 Python 对象映射到数据库表记录。

scripts/: 数据脚本

import_jl_to_db.py: 将 output/records/ 目录下的 JSON Lines 文件批量导入到 PostgreSQL 数据库的工具脚本，用于数据迁移或恢复。

metabase/ - 数据可视化
存放所有与 Metabase 报表和看板相关的配置。

Dockerfile-meta: 定制 Metabase 镜像。基于官方 Metabase 镜像，额外安装 PostgreSQL 驱动、中文字体包等，以满足项目特定需求。

init/: 初始化配置

automationOS_dashboard.json: 预置仪表盘定义。一个 JSON 文件，定义了“质量核心看板”的布局、图表和查询。当 Metabase 容器首次启动时，会自动导入这个文件，实现看板的自动化部署。

sql/: SQL 查询源文件。存放 automationOS_dashboard.json 中各个图表所使用的原生 SQL 查询语句。将 SQL 单独存放便于版本控制、审查和在数据库客户端中直接调试。

readme.md: Metabase 运维说明。记录 Metabase 的升级、备份、权限配置等操作指南。

output/ - 运行产物
存放项目运行时动态生成的各种文件。此目录通常被添加到 .gitignore 中，不提交到代码库。

logs/: 运行日志文件。

allure-results/: Allure 报告原始数据。存放 Allure 生成的 XML/JSON 结果文件。

screenshots/: 失败截图。存放测试用例失败时自动截取的屏幕快照。

records/: 文件模式记录。当 SETTINGS.record_mode 设置为 file 时，测试结果会以 JSON Lines (.jl) 格式写入此目录，作为数据库记录的替代或备份。

tests/ - 单元/集成测试
run.py: 本地运行入口。一个简单的 Python 脚本，用于在本地触发 pytest 命令，方便在 IDE 中进行调试。
