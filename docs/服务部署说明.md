## 🎯 部署概述

### 支持的部署方式

1. **传统部署**：直接在服务器上安装和配置
2. **Docker 单容器**：单个应用容器部署
3. **Docker Compose**：多服务容器编排部署
4. **Kubernetes**：容器集群部署（生产环境推荐）

### 服务组件

- **OpenMautoTest 主应用**：测试执行引擎
- **PostgreSQL**：数据存储（可选，支持文件存储降级）
- **Redis**：缓存和会话存储（可选）
- **Nginx**：反向代理和静态文件服务
- **Metabase**：数据可视化平台
- **Allure**：测试报告服务
- **Jenkins**：CI/CD 服务（可选）

## 🔧 环境准备

### 基础系统要求

| 组件 | 最低配置 | 推荐配置 |
|------|----------|----------|
| CPU | 2 核心 | 4 核心 |
| 内存 | 4GB | 8GB |

| 操作系统 | Ubuntu 18.04+ / CentOS 7+ / Windows 10+ | Ubuntu 20.04+ |

| 服务 | 端口 | 协议 | 说明 |
|------|------|------|------|
| OpenMautoTest | 8080 | HTTP | 主应用服务 |

| Nginx | 80/443 | HTTP/HTTPS | 反向代理 |

### 4. 服务配置

#### 创建 systemd 服务文件

```bash
# 创建服务文件
sudo tee /etc/systemd/system/openmautotest.service << EOF
[Unit]
Description=OpenMautoTest Service
After=network.target postgresql.service redis.service
Requires=network.target

[Service]
Type=simple
User=openmautotest
Group=openmautotest
WorkingDirectory=/home/openmautotest/openmautotest
Environment=PYTHONPATH=/home/openmautotest/openmautotest
Environment=PYTHONUNBUFFERED=1
ExecStart=/home/openmautotest/openmautotest/venv/bin/python -m uvicorn main:app --host 0.0.0.0 --port 8080
ExecReload=/bin/kill -HUP \$MAINPID
Restart=always
RestartSec=10
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
EOF

# 重新加载 systemd 配置
sudo systemctl daemon-reload

# 启动服务
sudo systemctl start openmautotest
sudo systemctl enable openmautotest

# 检查服务状态
sudo systemctl status openmautotest
```

#### Nginx 反向代理配置

```bash
# 创建 Nginx 配置文件
sudo tee /etc/nginx/sites-available/openmautotest << EOF
server {
    listen 80;
    server_name your-domain.com;  # 替换为您的域名
    
    # 反向代理到应用
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host \$host;
        proxy_set_header X-Real-IP \$remote_addr;
        proxy_set_header X-Forwarded-For \$proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto \$scheme;
    }
    
    # 静态文件服务
    location /output/ {
        alias /home/openmautotest/openmautotest/output/;
        autoindex on;
    }
    
    # 健康检查
    location /health {
        proxy_pass http://127.0.0.1:8080/health;
        access_log off;
    }
}
EOF

# 启用站点
sudo ln -s /etc/nginx/sites-available/openmautotest /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl restart nginx
```

## 🐳 Docker 部署

### 1. Docker 环境准备

#### 安装 Docker

**Ubuntu 系统：**
```bash
# 更新包索引
sudo apt update

# 安装依赖
sudo apt install -y apt-transport-https ca-certificates curl gnupg lsb-release

# 添加 Docker GPG 密钥
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /usr/share/keyrings/docker-archive-keyring.gpg

# 添加 Docker 仓库
echo "deb [arch=amd64 signed-by=/usr/share/keyrings/docker-archive-keyring.gpg] https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# 安装 Docker
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io

# 启动 Docker 服务
sudo systemctl start docker
sudo systemctl enable docker

# 添加当前用户到 docker 组
sudo usermod -aG docker $USER
```

**CentOS 系统：**
```bash
# 安装依赖
sudo yum install -y yum-utils device-mapper-persistent-data lvm2

# 添加 Docker 仓库
sudo yum-config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo

# 安装 Docker
sudo yum install -y docker-ce docker-ce-cli containerd.io

# 启动 Docker 服务
sudo systemctl start docker
```

### 3. Nginx 配置

```nginx
# /etc/nginx/sites-available/openmautotest
upstream openmautotest_app {
    server 127.0.0.1:8080;
    keepalive 32;
}

server {
    listen 80;
    server_name your-domain.com;
    
    # 安全头
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-XSS-Protection "1; mode=block" always;
    
    # 应用代理
    location / {
        proxy_pass http://openmautotest_app;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
        
        # 超时设置
        proxy_connect_timeout 30s;
        proxy_send_timeout 30s;
        proxy_read_timeout 30s;
    }
    
    # 静态文件
    location /output/ {
        alias /home/openmautotest/openmautotest/output/;
        autoindex on;
        autoindex_exact_size off;
        autoindex_localtime on;
        
        # 缓存设置
        location ~* \.(jpg|jpeg|png|gif|ico|css|js)$ {
            expires 1M;
            add_header Cache-Control "public, immutable";
        }
    }
    
    # 健康检查
    location /health {
        proxy_pass http://openmautotest_app/health;
        access_log off;
    }
    
    # Gzip 压缩
    gzip on;
    gzip_vary on;
    gzip_min_length 1024;
    gzip_types text/plain text/css text/xml text/javascript application/json application/javascript application/xml+rss application/atom+xml image/svg+xml;
}
```

#### 应用性能监控

```python
# 性能监控脚本 monitor.py
import requests
import time
import psutil
import json

def monitor_application():
    """监控应用性能"""
    try:
        # HTTP 响应时间
        start_time = time.time()
        response = requests.get('http://localhost:8080/health')
        response_time = time.time() - start_time
        
        # 系统资源
        cpu_percent = psutil.cpu_percent()
        memory = psutil.virtual_memory()
        disk = psutil.disk_usage('/')
        
        metrics = {
            'timestamp': time.time(),
            'http_response_time': response_time,
            'http_status_code': response.status_code,
            'cpu_percent': cpu_percent,
            'memory_percent': memory.percent,
            'disk_percent': disk.percent,
        }
        
        print(json.dumps(metrics, indent=2))
        
    except Exception as e:
        print(f"Monitoring error: {e}")

if __name__ == "__main__":
    monitor_application()
```

```bash
# backup.sh

BACKUP_DIR="/backup/openmautotest"
DATE=$(date +%Y%m%d_%H%M%S)

# 创建备份目录
mkdir -p $BACKUP_DIR

# 数据库备份
pg_dump -h localhost -U openmautotest_user openmautotest > $BACKUP_DIR/db_backup_$DATE.sql

# 应用数据备份
tar -czf $BACKUP_DIR/app_data_$DATE.tar.gz ~/openmautotest/output

# 配置文件备份
tar -czf $BACKUP_DIR/config_$DATE.tar.gz ~/openmautotest/.env ~/openmautotest/configs

# 清理旧备份（保留30天）
find $BACKUP_DIR -name "*.sql" -mtime +30 -delete
find $BACKUP_DIR -name "*.tar.gz" -mtime +30 -delete

echo "Backup completed: $DATE"
```

#### 自动备份设置

```bash
# 添加到 crontab
crontab -e

# 每天凌晨2点执行备份
0 2 * * * /home/openmautotest/scripts/backup.sh >> /var/log/openmautotest-backup.log 2>&1
```

## 🚨 故障排除

### 1. 常见问题

#### 应用无法启动

**症状**：服务启动失败或立即退出

**排查步骤**：
```bash
# 检查服务状态
sudo systemctl status openmautotest

# 查看错误日志
sudo journalctl -u openmautotest -n 50

# 检查配置文件
python -c "from configs.settings import get_settings; print(get_settings())"

# 检查端口占用
sudo netstat -tulpn | grep 8080

# 检查文件权限
ls -la ~/openmautotest/
```

**解决方案**：
- 检查配置文件语法
- 确认端口未被占用
- 检查文件权限和所有者
- 验证依赖是否完整安装

#### 数据库连接失败

**症状**：数据库连接错误或超时

**排查步骤**：
```bash
# 检查 PostgreSQL 服务
sudo systemctl status postgresql

# 测试数据库连接
psql -h localhost -U openmautotest_user -d openmautotest

# 检查数据库配置
sudo -u postgres psql -c "\l" | grep openmautotest

# 检查网络连接
telnet localhost 5432
```

**解决方案**：
- 启动 PostgreSQL 服务
- 检查数据库用户权限
- 验证连接字符串格式
- 检查防火墙设置

#### 浏览器启动失败

**症状**：Playwright 浏览器无法启动

**排查步骤**：
```bash
# 检查浏览器安装
playwright install --dry-run

# 测试浏览器启动
python -c "from playwright.sync_api import sync_playwright; p = sync_playwright().start(); browser = p.chromium.launch(); browser.close(); p.stop()"

# 检查系统依赖
playwright install-deps

# 检查 X11 转发（如果是远程服务器）
echo $DISPLAY
```

**解决方案**：
- 重新安装浏览器：`playwright install`
- 安装系统依赖：`playwright install-deps`
- 启用无头模式：`BROWSER_HEADLESS=true`
- 检查显示设置（GUI 环境）

#### 内存不足

**症状**：应用因内存不足被杀死

**排查步骤**：
```bash
# 检查内存使用
free -h
ps aux --sort=-%mem | head -10

# 检查系统日志
dmesg | grep -i "killed process"
journalctl | grep -i "out of memory"

# 检查交换空间
swapon --show
```

**解决方案**：
- 增加系统内存
- 配置交换空间
- 调整并行worker数量
- 优化应用内存使用

### 2. 性能问题

#### 响应时间慢

**排查步骤**：
```bash
# 检查系统负载
uptime
top

# 检查网络延迟
ping localhost
curl -w "@curl-format.txt" -o /dev/null -s http://localhost:8080/health

# 检查数据库性能
sudo -u postgres psql -c "SELECT * FROM pg_stat_activity;"

# 检查磁盘 I/O
iotop -ao
```

**优化建议**：
- 增加 worker 进程数
- 优化数据库查询
- 启用缓存（Redis）
- 使用 SSD 存储

#### 高并发问题

**排查步骤**：
```bash
# 检查连接数
netstat -an | grep :8080 | wc -l

# 检查文件描述符限制
ulimit -n

# 检查系统限制
cat /proc/sys/fs/file-max
```

**优化配置**：
```bash
# 增加文件描述符限制
echo "* soft nofile 65535" >> /etc/security/limits.conf
echo "* hard nofile 65535" >> /etc/security/limits.conf

# 调整内核参数
echo "net.core.somaxconn = 65535" >> /etc/sysctl.conf
echo "net.ipv4.tcp_max_syn_backlog = 65535" >> /etc/sysctl.conf
sysctl -p
```


### 4. 网络问题

#### 端口无法访问

**排查步骤**：
```bash
# 检查端口监听
sudo netstat -tulpn | grep -E "8080|80|443"

# 检查防火墙
sudo ufw status
sudo iptables -L

# 检查 SELinux（CentOS/RHEL）
sestatus
```

**解决方案**：
```bash
# 开放端口（UFW）
sudo ufw allow 8080
sudo ufw allow 80
sudo ufw allow 443

# 开放端口（iptables）
sudo iptables -A INPUT -p tcp --dport 8080 -j ACCEPT
sudo iptables-save > /etc/iptables/rules.v4
```
