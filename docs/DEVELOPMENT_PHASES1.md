# OpenMautoTest 开发阶段指导书（第1部分：阶段1-5）

本文档定义了OpenMautoTest项目的前5个开发阶段。每个阶段必须按顺序完成，完成当前阶段所有目标并记录开发日志后，方可进入下一阶段。

---

## 阶段1：项目基础架构搭建

### 开发任务
1. **项目目录结构创建**
   - 根据`docs/项目架构文档.md`创建完整的目录结构
   - 创建所有必需的`__init__.py`文件
   - 创建基础配置文件模板

2. **依赖管理配置**
   - 编写`requirements.txt`文件，包含所有必需的Python包：
     - pytest (测试框架)
     - playwright (Web端自动化)
     - minium (小程序自动化，需Node.js 16+)
     - sqlalchemy (数据库ORM)
     - alembic (数据库迁移)
     - allure-pytest (测试报告)
     - python-dotenv (环境变量管理)
   - 配置`pyproject.toml`文件，定义项目元数据和构建配置
   - 创建`.env.example`环境变量模板文件，包含DATABASE_URL、JENKINS_URL等关键配置

3. **基础工具配置**
   - 创建`Makefile`，定义常用的项目命令：
     - `make test` (运行测试)
     - `make check-config` (配置检查)
     - `make meta-up` (启动Metabase服务)
     - `make migrate` (执行数据库迁移)
   - 配置Docker相关文件（`docker-compose.meta.yml`）用于快速启动Metabase和PostgreSQL
   - 设置基础的`.gitignore`文件，排除output/目录、.env文件等

### 阶段目标
- 完整的项目目录结构已创建
- 所有基础配置文件已就位
- 项目依赖管理体系已建立
- 开发环境可以正常初始化

### 必带的额外目标说明
- **前后端接口检查**：虽然本阶段主要是架构搭建，但需要确保配置文件中的API接口配置格式正确
- **程序运行检查**：确保项目可以正常初始化，`python -m pytest --version`等基础命令可以执行
- **代码文件行数控制**：每个配置文件不超过500行，复杂配置需要拆分成多个文件
- **环境依赖验证**：确保Python 3.8+、Node.js 16+、Docker & Docker Compose环境就绪

### 完成标准
- [ ] 所有目录和文件按架构文档创建完成
- [ ] `pip install -r requirements.txt`可以正常执行
- [ ] `make --version`命令可以正常运行
- [ ] 项目结构符合架构设计要求

## 阶段4：数据库模型和数据持久化系统

### 开发任务
1. **数据模型定义**
   - 实现`db/models/record.py`测试结果数据模型
   - 根据需求文档定义`test_case_runs`表结构，包含以下字段：
     - id (BIGINT, PRIMARY KEY): 唯一标识符
     - run_id (VARCHAR(255), NOT NULL): 单次任务ID
     - project_name (VARCHAR(100)): 项目/团队名称
     - flow_name (VARCHAR(255)): 业务流程名称
     - test_case_name (TEXT, NOT NULL): 测试用例名称
     - status (VARCHAR(20), NOT NULL): 执行结果 (passed/failed/skipped)
     - environment (VARCHAR(50)): 测试环境
     - start_time/end_time (TIMESTAMPTZ, NOT NULL): 开始/结束时间
     - duration (FLOAT): 执行耗时(秒)
     - failure_reason (TEXT): 失败原因
     - retry_attempt (INTEGER, DEFAULT 0): 重试次数
     - jenkins_build_url (TEXT): 构建链接
   - 使用SQLAlchemy ORM映射数据库表

2. **数据库迁移系统**
   - 配置Alembic数据库迁移工具
   - 创建初始化迁移脚本`db/migrations/versions/001_init_automationos.py`
   - 实现数据库版本管理机制

3. **数据记录器开发**
   - 实现`orchestrator/recorder.py`数据持久化模块
   - 支持批量数据写入和异常处理：
     - 批量写入模式，每批次最多100条记录
     - 写入失败时的重试机制，最多重试3次
     - 写入失败不影响测试执行，仅记录警告日志
   - 实现异常处理机制：
     - 数据库连接异常：自动重试连接，失败后降级到本地文件记录
     - 数据格式异常：记录错误日志并跳过异常数据
     - 磁盘空间不足：清理历史日志文件并告警

### 阶段目标
- 完整的数据模型已定义
- 数据库迁移系统正常工作
- 数据持久化机制稳定可靠
- 支持数据批量处理和异常恢复

### 必带的额外目标说明
- **前后端接口检查**：确保数据模型字段与前端展示需求一致，数据库连接配置正确
- **程序运行检查**：数据库连接正常，迁移脚本可以成功执行，数据写入功能正常
- **代码文件行数控制**：数据模型文件不超过500行，复杂模型拆分为多个文件

### 完成标准
- [ ] 数据库表结构创建成功
- [ ] 数据模型可以正常进行CRUD操作
- [ ] 数据库迁移脚本执行成功
